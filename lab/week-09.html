Lab guide 9

Mitigating Controls and Asset Management

The first Security Operations week — the technical controls you'd actually deploy, and tracking what you own.

10-12 hours Week 8 complete. You'll need sudo rights on secure-target.
Before you start
  • secure-target VM up
  • firewalld (Rocky) or ufw (Ubuntu) available

1. Configure a host firewall with least-privilege rules

Allow only what's needed — the practical version of least privilege from Week 1.

Rocky/RHEL-family (firewalld)
sudo firewall-cmd --list-all
sudo firewall-cmd --remove-service=cockpit --permanent 2>/dev/null
sudo firewall-cmd --add-service=ssh --permanent
sudo firewall-cmd --reload
Ubuntu (ufw)
sudo ufw status verbose
sudo ufw default deny incoming
sudo ufw allow ssh
sudo ufw enable

2. Set SELinux or AppArmor to enforcing, then resolve a denial

Mandatory access control — a second layer behind standard permissions.

Rocky/RHEL-family (SELinux)
sudo setenforce 1
sestatus
# Trigger a denial on purpose by moving a web file to a non-standard context, then check the log
sudo ausearch -m avc -ts recent 2>/dev/null | tail -20
Ubuntu (AppArmor)
sudo aa-status
sudo aa-enforce /etc/apparmor.d/* 2>/dev/null | tail -5

3. Deception and disruption technology

A honeypot is a single decoy system; a honeynet is a whole decoy network; a honeyfile is a single fake-but-tempting file; a honeytoken is fake data (like a credential) planted specifically to detect misuse; a canary account is a dormant account that should never be used — any login attempt on it is a near-certain compromise indicator. None of these stop an attack; they're built to detect and waste an attacker's time.

4. Set up a simple honeypot-style trap on an unused port

The concept, at minimal scale.

Listen on an unused port and log any connection attempt
sudo nc -lvp 9999 &
# From kali-tools: nc -zv secure-target.lab 9999
# Check the listener's output — every connection to an unused port is inherently suspicious

5. Email security: DMARC, SPF, and DKIM

SPF lists which mail servers are allowed to send email for a domain. DKIM cryptographically signs outgoing mail so receivers can verify it wasn't altered in transit. DMARC tells receiving servers what to do when SPF or DKIM fails (quarantine, reject, or just report) — it's the policy layer that ties the other two together. Together they're the primary defense against email spoofing, which underpins most phishing and business email compromise.

6. Full asset life cycle

Walk any asset through: planning/scoping (do we need this, what will it access), acquisition/procurement (vetted purchase, not shadow IT), assignment/accounting (who owns it, is it in inventory), monitoring/tracking (is it patched, is it still where it should be), and disposal/decommissioning (wiped or destroyed before it leaves your control — a shockingly common source of real data breaches is improperly disposed-of hardware).

Check your work

Run these before you consider the lab finished.

  1. Firewall shows only the intended services allowed
  2. SELinux/AppArmor is confirmed in enforcing mode
  3. The honeypot listener logs the test connection from kali-tools
  4. You can walk all five asset life cycle stages from memory
