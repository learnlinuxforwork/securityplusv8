Lab guide 2

Change Management and Cryptography

Two objectives that don't look related until you realize every crypto rollout is itself a change that needs a CAB's sign-off.

10-12 hours Week 1 complete
Before you start
  • secure-target VM up
  • openssl installed (it ships by default on both Rocky and Ubuntu)

1. Walk a change through a CAB

A Change Advisory Board (CAB) reviews proposed changes before they hit production. A real request includes: what's changing and why (ownership, stakeholders), an impact analysis (what could this break), test results, and a backout plan (exactly how you'd undo it if it goes wrong) — plus a scheduled maintenance window so the blast radius is predictable. "Fail forward" means choosing to push a fix ahead rather than roll back, when rolling back is riskier than moving forward — a legitimate call, but one the CAB should make deliberately, not by accident.

2. Technical implications of a change

Before you approve anything, ask what it touches: does it require downtime or a service/application restart? Does it affect an allow list or deny list? Are there legacy application dependencies that assume the old behavior? Documentation — updated diagrams, updated policies, and version control on configuration — is part of the change, not an afterthought.

3. Generate a private key and a self-signed certificate

The foundation of PKI: a key pair, and a certificate that says who the public key belongs to.

Generate an RSA key pair, then a self-signed cert from it
openssl genrsa -out lab.key 2048
openssl req -new -x509 -key lab.key -out lab.crt -days 365 -subj '/CN=lab.securityplusv8.local'
openssl x509 -in lab.crt -noout -text | head -20

4. Generate a certificate signing request (CSR)

In the real world, you'd send this to a CA instead of self-signing.

Build a CSR from the same key
openssl req -new -key lab.key -out lab.csr -subj '/CN=lab.securityplusv8.local'
openssl req -in lab.csr -noout -text | head -10

5. What a CA actually does with a CSR

A Certificate Authority verifies you control the domain/identity in the CSR, then signs it with the CA's own private key — creating a chain of trust back to a root of trust your browser or OS already trusts. If a certificate is compromised before it expires, the CA can revoke it via a Certificate Revocation List (CRL) or answer real-time revocation checks via OCSP.

6. Symmetric vs. asymmetric, hands-on

Same data, two completely different key models.

Symmetric: one key encrypts and decrypts
echo 'confidential lab data' > secret.txt
openssl enc -aes-256-cbc -pbkdf2 -salt -in secret.txt -out secret.enc -pass pass:labpassword123
openssl enc -aes-256-cbc -pbkdf2 -d -in secret.enc -pass pass:labpassword123
Asymmetric: the public key encrypts, only the private key decrypts
openssl rsa -in lab.key -pubout -out lab.pub
openssl pkeyutl -encrypt -pubin -inkey lab.pub -in secret.txt -out secret.rsa.enc
openssl pkeyutl -decrypt -inkey lab.key -in secret.rsa.enc

7. Hash a file, then salt a password

Hashing is one-way; salting defeats precomputed rainbow-table attacks against it.

Hash the same file twice — identical output, every time
sha256sum secret.txt
sha256sum secret.txt
The same password, two different salts, two completely different hashes
echo -n 'password123saltAAA' | sha256sum
echo -n 'password123saltBBB' | sha256sum

Check your work

Run these before you consider the lab finished.

  1. openssl x509 -in lab.crt -noout -subject # shows your CN
  2. ls -l lab.key lab.crt lab.csr # all three files exist
  3. openssl enc -aes-256-cbc -pbkdf2 -d -in secret.enc -pass pass:labpassword123 # decrypts cleanly
  4. You can explain what a CRL and OCSP each check, and why they're different
Break it, then fix it

Break:

openssl enc -aes-256-cbc -pbkdf2 -d -in secret.enc -pass pass:wrongpassword

What you'll see: A decrypt error — 'bad decrypt' or similar. Wrong key material, no way around it.

Fix:

openssl enc -aes-256-cbc -pbkdf2 -d -in secret.enc -pass pass:labpassword123

Why it matters: Symmetric encryption has no recovery path if the key (or passphrase deriving it) is wrong or lost — that's exactly why key escrow exists as a formal recovery mechanism for organizations, not a personal habit of writing passwords on a sticky note.
