Lab guide 1

Security Concepts and Controls

The vocabulary you'll reuse in every other week: CIA, AAA, Zero Trust, and how to classify any control you'll ever encounter.

8-10 hours secure-target VM installed
Before you start
  • secure-target (Rocky Linux or Ubuntu Server) installed
  • A terminal open on it

1. The CIA triad, with real violations

Every security control exists to protect one of three properties: Confidentiality (only authorized people can read the data), Integrity (the data hasn't been tampered with), and Availability (authorized people can actually get to it when they need it). A ransomware attack violates availability. A leaked customer database violates confidentiality. A tampered financial record violates integrity. Most real incidents violate more than one at once.

2. See AAA in action

Authentication, authorization, and accounting are three separate, sequential steps — not one blob called "login."

Authenticate as yourself, then check what you're authorized to do
whoami
id
sudo -l
See the accounting trail your own login just created
last -n 5
sudo journalctl _COMM=sshd -n 10 --no-pager 2>/dev/null || echo 'no sshd logins yet — that is fine'

3. Non-repudiation and least privilege

Non-repudiation means a user can't credibly deny having done something — a signed, logged action tied to a specific identity, not a shared account. Least privilege means every account gets exactly the access it needs and nothing more. A shared "admin" login that five people use defeats both principles at once: nobody can prove who did what, and everybody has more access than most of their work requires.

4. Least privilege, demonstrated

Create an account that can do exactly one privileged thing — not everything.

A user who can only restart one specific service, via sudo
sudo useradd -m webops
echo 'webops ALL=(root) NOPASSWD: /usr/bin/systemctl restart sshd' | sudo tee /etc/sudoers.d/webops
sudo -l -U webops

5. Zero Trust, in one paragraph you could say out loud

Traditional network security assumed anything inside the firewall was trusted. Zero Trust assumes the opposite: never trust, always verify — every request gets authenticated and authorized regardless of whether it came from inside or outside the network. In practice that means verifying device health and user identity on every request, not just at the network perimeter once.

6. Classify five controls

Every control has a category (technical/logical, managerial/administrative, physical/environmental, or operational) and a type (preventive, deterring, detective, corrective, compensating, or directive). Classify these five out loud before you check yourself: a firewall rule (technical, preventive), a security awareness policy (managerial, directive), a fence around a data center (physical, deterring), a security camera (physical, detective), an incident response runbook (operational, corrective), a compensating control like extra logging when you can't patch a legacy system (technical, compensating).

Check your work

  1. id webops # account exists
  2. sudo -l -U webops # shows the one allowed command, nothing more
  3. You can define CIA, AAA, non-repudiation, least privilege, and Zero Trust from memory, no notes
  4. You can name the category AND type for all five sample controls above
