Lab guide 5

Vulnerability Types and AI-Related Risk

The gaps attackers walk through — and the newest category CompTIA added: AI-specific threats.

8-10 hours Week 4 complete
Before you start
  • secure-target and kali-tools VMs up

1. Find what's outdated on secure-target

Unsupported, unpatched, and obsolete systems are the single most common real-world root cause in breach reports.

Check for available updates and how far behind you are
sudo dnf check-update 2>/dev/null || sudo apt update && apt list --upgradable 2>/dev/null | head -20

2. Race conditions: TOC and TOU

A time-of-check to time-of-use (TOC/TOU) vulnerability happens when a program checks a condition (file permissions, a value) and then acts on it later — and something changes in between. Classic example: a script checks that a file isn't a symlink, then opens it by path a moment later, after an attacker has swapped it for a symlink to a sensitive file. The fix is almost always "check and use atomically," not "check, then trust."

3. Find a hardcoded secret in a sample repo

One of the most common, embarrassingly simple real vulnerabilities.

A safe, self-contained example — grep for common secret patterns
mkdir -p ~/secplus-lab/sample-repo && cd ~/secplus-lab/sample-repo
printf 'DB_PASSWORD="Summer2024!"\napi_key = "sk_test_51H8x9K2L"\n' > config.py
grep -inE 'password|api_key|secret|token' config.py

4. Zero-days, misconfiguration, and shadow IT

A zero-day is a vulnerability with no available patch — sometimes not even publicly known yet. Misconfiguration is the human-error version of the same problem: a default password left in place, a storage bucket left public, an overly permissive firewall rule. Shadow IT is hardware or software running in an environment without IT's knowledge or approval — impossible to patch or monitor because nobody officially knows it's there.

5. Check for a real misconfiguration on secure-target

Public object storage and overly-open permissions are the same root problem at different scales.

Find world-writable files — a classic misconfiguration
find /etc -perm -002 -type f 2>/dev/null
find ~ -perm -002 -type f 2>/dev/null

6. AI-specific threats and vulnerabilities

This is a new objective, and it's specific: model manipulation and poisoning corrupt an AI system's training data or behavior. Prompt injection tricks an LLM into ignoring its instructions via crafted input. Hallucination is the model confidently generating false information. Jailbreaking bypasses a model's safety guardrails. Data loss and privacy risks arise when sensitive information fed into a prompt leaks into logs, training data, or another user's session. None of these are hypothetical — they're the reason organizations need an AI usage policy at all.

Check your work

Run these before you consider the lab finished.

  1. grep output finds the sample hardcoded credentials
  2. find command completes and lists any world-writable files found (or none, if secure-target is already clean)
  3. You can explain prompt injection and model poisoning as two distinct AI risks, not the same thing
